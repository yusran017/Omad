PROMPT สำหรับ AI: สร้าง OMAD Tracker PWA สำหรับมือถือ

เป้าหมาย
สร้างเว็บแอปติดตามการกินแบบ OMAD (One Meal A Day) ที่ออกแบบ Mobile First และติดตั้งเป็น PWA ได้จาก Google Chrome บน Android โดยโค้ดทั้งหมดสามารถนำไปอัปโหลด GitHub และใช้งานผ่าน GitHub Pages ได้

แนวคิดหลัก
แอปต้องตอบให้ผู้ใช้เห็นทันทีว่า:
- วันนี้เปิดการติดตาม OMAD อยู่หรือไม่
- ตอนนี้อยู่ในช่วง FASTING หรือ EATING
- Fasting มาแล้วกี่ชั่วโมง/นาที
- เหลือเวลาเท่าไรเมื่อมีเป้าหมาย
- วันนี้กินแล้วหรือยัง
- กินเวลาใด
- ประวัติย้อนหลังเป็นอย่างไร
- ความสม่ำเสมอใน 7 / 30 / 90 วันเป็นอย่างไร

==================================================
1. PLATFORM / TECHNICAL REQUIREMENTS
==================================================

สร้างเป็น PWA มาตรฐานที่ใช้งานบน Google Chrome ได้ดี

ต้องมี:
- HTML5
- CSS3
- Vanilla JavaScript หรือ JavaScript ที่ไม่ทำให้โปรเจกต์ซับซ้อนเกินจำเป็น
- manifest.json
- service-worker.js
- Offline support
- Responsive design
- HTTPS-compatible
- ติดตั้งเป็น PWA ได้
- เหมาะกับ GitHub Pages
- ไม่ต้องมี backend ในเวอร์ชันแรก
- เก็บข้อมูลในเครื่องด้วย IndexedDB เป็นหลัก หรือ localStorage หากเหมาะสม
- มีระบบ Export / Import JSON เพื่อสำรองข้อมูล

ไม่ต้องทำระบบ Login ในเวอร์ชันแรก

==================================================
2. DESIGN / UI
==================================================

ต้องการ UI ที่สวย ทันสมัย มีสีสัน และดูเหมือนแอปมือถือจริง ไม่ใช่หน้าเว็บธรรมดา

สไตล์ที่ต้องการ:
- Modern Mobile Dashboard
- 3D / Soft Glass / Glassmorphism แบบพอดี
- Gradient
- Card มีมิติเล็กน้อย
- Rounded corners
- Icon ชัดเจน
- Typography อ่านง่าย
- มี Dark Mode และ Light Mode
- สีหลักเกี่ยวกับพลังงาน/การอดอาหาร เช่น ส้ม เหลือง แดง ชมพู ม่วง น้ำเงิน และสีเขียวสำหรับสถานะสำเร็จ
- อย่าใช้สีมากจนอ่านยาก
- ใช้สีเพื่อสื่อสถานะอย่างชัดเจน

ต้องมี Animation แบบเบา ๆ เช่น:
- Progress ring
- ปุ่มเปลี่ยนสถานะ
- Card transition
- Timer update
- Success animation

หลีกเลี่ยง animation ที่ทำให้เครื่องช้า

==================================================
3. SCREEN WIDTH / RESPONSIVE
==================================================

นี่เป็นข้อกำหนดสำคัญมาก

ออกแบบ Mobile First แต่ต้องรองรับ:
- โทรศัพท์จอเล็ก
- โทรศัพท์จอ 6 นิ้วขึ้นไป
- โทรศัพท์จอกว้าง
- Tablet
- Desktop

บนโทรศัพท์:
- เนื้อหาต้องพอดีกับความกว้างหน้าจอ
- ห้ามมี horizontal scroll
- ห้ามมีองค์ประกอบล้นออกนอกจอ
- ไม่ให้เกิดพื้นที่ว่างซ้ายและขวามากเกินไป
- ใช้ความกว้างหน้าจออย่างคุ้มค่า
- margin ด้านข้างเพียงเล็กน้อย เช่นประมาณ 12–16px
- Card ควรกว้างเกือบเต็มหน้าจอ
- ปุ่มต้องกดง่ายด้วยนิ้ว
- ตัวเลข Timer ต้องใหญ่และอ่านง่าย

บน Desktop:
- ไม่ขยาย Card จนกว้างเกินไป
- ใช้ max-width ที่เหมาะสม
- สามารถจัด layout เป็น 2 columns หรือ dashboard ได้เมื่อพื้นที่มากขึ้น

ห้ามออกแบบแบบ Desktop-first แล้วบีบให้เหลือมือถือ

==================================================
5. ACTIVE / NOT ACTIVE
==================================================

ต้องมี Toggle ที่เข้าใจง่าย

ACTIVE = วันนี้กำลังติดตาม OMAD
NOT ACTIVE = วันนี้ไม่ได้ติดตาม OMAD

ไม่ควรตีความ NOT ACTIVE ว่าเป็นความล้มเหลว

ตัวอย่าง:

[ 🟢 ACTIVE ]

เมื่อกด:
- เปิดการติดตามวันนี้
- สร้าง session ของวันนี้
- เริ่มเก็บ timestamp

เมื่อปิด:
[ ⚪ NOT ACTIVE ]

ระบบต้องไม่บันทึกว่าเป็นวันที่ล้มเหลวโดยอัตโนมัติ

ควรมี Confirm ก่อนปิดหากมี session ที่ยังไม่เสร็จ

ไม่ควรพึ่ง JavaScript ที่ต้องทำงานตลอด 24 ชั่วโมง
